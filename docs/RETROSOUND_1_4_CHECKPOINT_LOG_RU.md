## Состояние на CP-001: подтверждено по исходникам, но не по устройствам
- `app/src/main/AndroidManifest.xml`: зарегистрирован `CarMediaService` и `androidx.media3.session.MediaLibraryService`.
- `app/build.gradle.kts`: версия `1.4.0-test1`, debug applicationIdSuffix `.v14test` для параллельной установки рядом со старой версией.
- `CarMediaService.kt`: медиатека, выбранная папка и 10 демотреков заявлены; доступность/плавность воспроизведения в автомобиле ещё не проверялась.
- `MainActivity.kt`: SAF-доступ к дереву папки и сканирование в фоне присутствуют в коде.
- `app.js`: ручной импорт ограничен `slice(0,130)` — требуется исправление; большие списки рендерятся целиком — требует оптимизации; фон `fallbackUrl` создаётся через `URL.createObjectURL` и не сохраняется долговременно — требуется исправление.
- Текущая реализация персонажа и скинов не удовлетворяет доказанным образом требованию «премиальная 3D-модель без артефактов».
- Иконку нужно сверить с ранее утверждённой, не считать соответствующей до визуального сравнения.

- Ошибки ставятся в очередь Android WorkManager, отправляются только в HTTPS relay (если настроен `RETROSOUND_DIAGNOSTICS_ENDPOINT`) через доступный Wi-Fi либо мобильный интернет. Без интернета очередь сохраняется, повторная попытка запускается по сети; без relay — только локальный журнал.
- Отчёт не содержит содержимого файлов, текстов ошибок сторонних сервисов, треков и URI. Автоматической прямой отправки на Gmail/SMTP из APK нет, паролей внутри APK нет.
- Шаблон server relay находится в `diagnostics-relay/`. Для реальных писем нужно отдельно указать серверные `RESEND_API_KEY`, `REPORT_TO`, `REPORT_FROM` и URL HTTPS-приёмника; в репозитории их не сохранять.
- Факт сборки, видимость на телефоне, реальная доставляемость писем и Android Auto должны проверяться отдельно после CI. Не выдавать поддержку механизма за доказательство доставки.
